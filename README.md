# cyber-enconvo

Enconvo packaging for https://github.com/briiirussell/cybersecurity-skills and https://github.com/cloudflare/security-audit-skill: all skills packaged as one updatable plugin.
Generated by the repo-to-plugin project skill; upstream clones stay pristine - never edit them.

## Install

```sh
npx -p @enconvo/api enconvo plugin install Iteractive-Development/cyber-enconvo
```

or **Plugins → Add → Add from GitHub…** and paste `Iteractive-Development/cyber-enconvo`.

## What a fresh install delivers

Everything the plugin ships loads through documented Enconvo mechanisms, with no post-install step:

- **43 skills** — every `skills/<name>/SKILL.md` is loaded globally (Plugin Formats › Skills: "Enconvo loads every `skills/<name>/SKILL.md`"). Every Agent sees every enabled skill.
- **9 helper agents** — every `agents/<name>.md` loads as a helper an agent can hand work to, and appears in the composer's `@` menu (Plugin Formats › Agents, Enconvo 2.5.7+): `appsec`, `offensive`, `detect`, `cloud`, `ai`, `govern`, `compliance`, `audit`, `finding-verifier`.

`finding-verifier` is the read-only per-finding refutation pass that `api-audit`, `owasp-audit` and `finding-triage` reference.

## About `allowed-tools`

Several skills carry `allowed-tools:` grant lists in their `SKILL.md` frontmatter. These are Claude Code fields: **Enconvo ignores them** (Plugin Formats: "`allowed-tools` and `model` are ignored: the agent keeps its usual tools, model and approvals"). In Enconvo the agent's own tool approvals apply. Do not treat the lists as a security boundary here.

## Optional: per-agent skill sets

By default every Agent sees all skills above. If you want an Agent to see only some of them, use Enconvo's per-Agent **Skills** setting (Settings → Agent List → the Agent → **Skills**) — the documented mechanism; add the skills you want it to carry and disable the rest for that Agent. Nothing in this repo needs to run for that, and no script here is a runtime dependency.

## Update flow

Installed from GitHub, the plugin updates with **Plugins → cyber-enconvo → Check for updates**, or by re-running the install command above.

To rebuild from the upstream repos (maintainer flow, needs the repo-to-plugin workspace):

```sh
python3 ~/Projects/Agent\ Plugins/.enconvo/skills/repo-to-plugin/scripts/new_plugin.py sync --config <adapter>/build-config.json
```

`build-config.json`, `agent-map.json` and `agents-state.json` are maintainer build inputs; Enconvo loads none of them. `agents/` is what ships the helpers.
